Settles retained sub-agent proposals produced by `delegate`, selected by `action`. `list` shows open proposals, each proposal's parent drift since its dispatch basis, and the typed conflicts between proposals; `show` returns one proposal's diff, changed files, change metadata, and conflict view by `proposal_id`. Conflicts compare post-images: identical writes are benign and omitted; different content or mode is `same_path_divergent`; a delete against a non-delete is `delete_modify`; a proposal path the parent changed is `parent_overlap`. A path whose content cannot be inspected falls back to `path_overlap`. Two lanes produce them: a worktree proposal keeps a live isolated worktree until you settle it and merges three-way; a container proposal's world is destroyed at seal, so the proposal is the whole-path delta manifest under `.yaah/proposals/<proposal_id>/` (host-target rehydrated on restart; session-target is a session-lifetime audit artifact), settled by writing whole-path post-images with no merge. To land the work: `select` fast-forwards onto the dispatch basis and fails closed if that basis moved since the dispatch; `apply` is path-disjoint onto a moved tree — three-way on the worktree lane, whole-path post-images on the container lane — and refuses if the parent changed any path the proposal also changes. The `strategy` parameter is valid only for `apply`: `path_disjoint` is the default, while `three_way` is an explicit worktree-only opt-in that runs Git's merge and fails closed on a textual conflict; the container lane remains whole-path. An apply refusal returns `status: "conflict"` with the overlap in `conflicts` (the paths may be empty when the parent basis can no longer be inspected) and leaves the proposal open; choose, discard, or resolve it. To not land it: `release` exports the delta to a retention path and then tears the worktree down (worktree lane only — a container world already ended at seal); `discard` throws the proposal away and removes its worktree, or its manifest directory.

The dispatch envelope carries `world` (`worktree` or `container`); a container dispatch or settlement envelope also carries `target` (`host` or `session`). An optional `warning` means the dispatch ran in a degraded world instead of the one requested — read it before deciding. An optional `notes` records a settlement caveat such as a failed teardown or stranded worktree. A session-target proposal settles into the session container; if `apply_out` is enabled in this session, use it to publish the accepted files to the host. The settlement verbs and the consume-once rule do not change.

Every response uses one envelope. `status` is `proposal` for a dispatch, `settled` after a verdict, `open` for `list`, `conflict` when an apply is refused by a path overlap, or `error` with the reason in `error`. A dispatch adds `proposal_id`, the changed `files`, a `diff`, an optional `result`, and a `next` list of legal verbs; a settlement adds the `action`, an optional `retained` release path, and the rendered `outcome`. A `conflict` response also carries a `strategy` when an apply was attempted and a `conflicts` array whose entries have `kind`, `paths`, and `proposals`, and may include `changes` and `details`; each change has `proposal_id`, `path`, `kind`, `base_digest`, `digest`, and `mode`, and each detail has `proposal_id`, `path`, and bounded `base`/`current`/`proposed` excerpts plus an optional `note`. The proposal remains open. A `list` response carries `proposals` summaries, each with `proposal_id`, `files`, `target`, optional `parent_drift` paths, optional `parent_drift_error` when the basis cannot be inspected, `changes`, optional `changes_error` when post-images cannot be inspected, its own `conflicts`, and its own `duplicates`, plus the global `conflicts` and `duplicates` arrays and `next`. A `show` response carries the same `changes`/`changes_error`, `conflicts`, and `duplicates` for that proposal. Identical post-images are not conflicts, but `apply` is path-disjoint, so only one side of a duplicate pair can land.
