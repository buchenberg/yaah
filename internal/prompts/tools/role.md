role(action, name?, description?, body?) — Creates and manages sub-agent role definitions stored as .md files with YAML frontmatter. `action: "list"` shows all roles loaded in the registry; roles carrying a non-default capability are annotated with their mode (`[primary]` or `[all]`) after the name, while default delegate-only roles render unannotated. `action: "show"` with a `name` returns the full role file. `action: "create"` with `name`, `description`, and `body` (markdown system prompt) writes a new role to the project roles directory; `create` and `edit` also accept optional `tools` (a JSON array or comma-separated list of tool names the role may use), a short `specialty` label, and `mode` — the capability: `primary` (orchestrator-eligible), `subagent` (delegate-only, the default), or `all` (both). On `create`, omitting `mode` means subagent and the key is omitted from the file; on `edit`, omitting `mode` leaves the existing value unchanged, and there is no unset via this tool — passing `subagent` restores the default capability but keeps the key, and removing the key is a direct file edit, not a tool operation. `action: "edit"` modifies an existing role. `action: "delete"` removes a role file. The registry is reloaded automatically after every mutation so list_subagents picks up changes immediately.
