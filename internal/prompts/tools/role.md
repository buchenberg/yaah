role(action, name?, description?, body?) — Creates and manages sub-agent role definitions stored as .md files with YAML frontmatter. `action: "list"` shows all roles loaded in the registry; roles carrying a non-default capability are annotated with their mode (`[primary]` or `[subagent]`) after the name, while default-capability roles render unannotated. `action: "show"` with a `name` returns the full role file. `action: "create"` with `name`, `description`, and `body` (markdown system prompt) writes a new role to the project roles directory; `create` and `edit` also accept optional `tools` (a JSON array or comma-separated list of tool names the role may use), a short `specialty` label, and `mode` — the capability: `primary` (orchestrator-eligible), `subagent` (delegate-only), or `all` (both). On `create`, omitting `mode` means `all` (the file-format default: orchestrator-capable unless marked otherwise) and the key is omitted from the file; on `edit`, omitting `mode` leaves the existing value unchanged, and there is no unset via this tool — passing `subagent` restores the delegate-only capability but keeps the key, and removing the key is a direct file edit, not a tool operation. On `create`, the written file is schema-complete by default: it carries a response contract (`## Changes` with files/summary/findings evidence pairs) and a working budget (max_iterations 100, max_turns 50, timeout 1200) matching the shipped worker-role shape — pass `contract_heading` and `contract_fields` (comma-separated names, optionally `name:evidence` or `name:interpretation`) to override the contract; budgets are per-role tuning and are set by editing the file directly. `action: "edit"` modifies an existing role. `action: "delete"` removes a role file. The registry is reloaded automatically after every mutation so list_subagents picks up changes immediately.

`tools` is an array of tool names (a comma-separated string is still accepted), and `contract_fields` is an array of `{name, kind}` objects (a comma-separated `name:kind` string is still accepted). `action` is optional and defaults to `list`.
