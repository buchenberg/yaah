Run a sub-agent with automatic rollback and retry on failure. BLOCKING — this call does not return until the sub-agent completes or all retries are exhausted. A git checkpoint of the workspace is taken before each attempt; if the sub-agent fails, its changes are rolled back and it is retried with guidance from the failure. Required params: `prompt` (the task) and `role` (sub-agent role; use list_subagents for details). Optional: `description` (short label), `timeout_seconds` (10-600 per attempt), `max_iterations` (1-50). Returns a JSON object for every outcome: `status` (`completed`, `failed`, `cancelled`, `rollback_failed`, `recheckpoint_failed`, or `exhausted`), `attempts` (number of sub-agent attempts used), plus `result` (on success) or `error` and `partial` (on failure). When turn checkpointing is enabled, `restores` (count) and `restored_from` (checkpoint id) report how many times a failed turn inside an attempt was rewound and retried. Check `status` first to distinguish success from a failed-and-rolled-back run. Use when correctness matters more than throughput; do NOT use for parallel or background work — use spawn_subagent for that.
