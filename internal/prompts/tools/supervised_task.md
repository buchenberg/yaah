Run a sub-agent with automatic rollback and retry on failure. BLOCKING — this call does not return until the sub-agent completes or all retries are exhausted. A git checkpoint of the workspace is taken before each attempt; if the sub-agent fails, its changes are rolled back and it is retried with guidance from the failure. Required params: `prompt` (the task) and `role` (sub-agent role; use list_subagents for details). Optional: `description` (short label), `timeout_seconds` (10-600 per attempt), `max_iterations` (1-50), `review` (boolean, default false — supervised review mode, see below). Returns a JSON object for every outcome: `status` (`completed`, `failed`, `cancelled`, `rollback_failed`, `recheckpoint_failed`, or `exhausted`), `attempts` (number of sub-agent attempts used), plus `result` (on success) or `error` and `partial` (on failure). When turn checkpointing is enabled, `restores` (count) and `restored_from` (checkpoint id) report how many times a failed turn inside an attempt was rewound and retried. Check `status` first to distinguish success from a failed-and-rolled-back run. Use when correctness matters more than throughput; do NOT use for parallel or background work — use spawn_subagent for that.

Review mode (`review: true`): instead of automatic retry, the sub-agent completes ONE work unit and you get a review envelope: `session_id`, `status` (`review`/`empty`/`cancelled`), `unit`, `result` (sub-agent report), `diff` (bounded patch of the unit's changes), `files`, optional `error`, and `next` (allowed verdicts). Drive the verdict cycle with the supervisor tool using `session_id`: `continue` (accept the unit, run the next one with optional guidance — the sub-agent keeps its conversation context), `rollback` (revert the unit's files AND conversation to the unit start, then rerun with your more specific `guidance` prompt), `fork` (rewind and run `prompt_a`/`prompt_b` as two competing variants from the same checkpoint; compare both diffs, then `choose` winner "a" or "b"), `review_diff` (re-fetch the diff), `accept` (keep the work, close the session), `abort` (rewind the unaccepted unit, close the session). While a review session is open you own the workspace: do not edit files yourself between verdicts — rollback and choose overwrite the working tree. Scope each work unit so it stays reviewable (one coherent change per unit).
