Rename a file inside the workspace. `path` is the source file and `to` is the destination path.

The file is moved by the substrate's own rename, so the bytes are never decoded, re-encoded, or passed through the model — a binary or non-UTF-8 file arrives unchanged. `path` and `to` are both resolved through the workspace path validator, so deny patterns and workspace-root containment apply exactly as they do for read, write, and delete.

Regular files only: directories, FIFOs, devices, and dangling symlinks are refused; a symlink that resolves to a regular file is handled by the usual path resolution, which transfers its target. A destination that is an existing directory or symlink is refused — pass the real path. An existing destination is refused unless `force` is true, in which case it is replaced (the check is best-effort against a writer racing the call from outside yaah; in-process dispatches are serialized). The destination's parent directory must already exist — create it first. Moving a file needs approval like every other mutating file tool. To leave the original in place, use `copy`; to remove a file outright, use `delete`.
