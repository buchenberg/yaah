Rename a file inside the workspace. `path` is the source file and `to` is the destination path.

The file is moved by the substrate's own rename, so the bytes are never decoded, re-encoded, or passed through the model — a binary or non-UTF-8 file arrives unchanged. `path` and `to` are both resolved through the workspace path validator, so deny patterns and workspace-root containment apply exactly as they do for read, write, and delete.

Regular files only: directories, FIFOs, sockets, and devices are refused. Symlinks follow the path layer: on the host a link is resolved first, so a source link to a regular file moves that target (leaving the link behind) and a dangling link is refused, while a destination link is followed so the clobber rule applies to its target; in the container sandbox resolution is lexical, so a symlink source or destination is refused — pass the real path. A destination that is an existing directory is always refused. An existing destination is refused unless `force` is true, in which case it is replaced (the check is best-effort against a writer racing the call from outside yaah; in-process dispatches are serialized). The destination's parent directory must already exist — create it with `mkdir` first, or pass `mkdir_p: true` to create the missing parents. Moving a file needs approval like every other mutating file tool. To leave the original in place, use `copy`; to remove a file outright, use `delete`; to move a whole directory, use `move_tree`.
