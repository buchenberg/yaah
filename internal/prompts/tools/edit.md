`edit(filePath, oldString, newString, replaceAll?, edits?)` — Exact string replacement in an existing file with fuzzy-match fallback. Arguments are matched literally; if `oldString` contains JSON-style escape sequences (`\u00e9`, `\n`) that do not match the file, the tool retries with them decoded and says so in the result. `newString` is never decoded: a literal backslash in the replacement is written verbatim, and when `oldString` was decoded the result notes if `newString` also contains escape sequences. Use `replace` for regex find-and-replace across multiple files; use `write` to create a new file; use `patch` to apply unified diff hunks.

Provide either `oldString`/`newString` or `edits[]`, not both: a call that sets both is refused rather than letting `edits[]` silently win.

Writes to the same file are serialized in-process, so a same-file pair in one batch is ordered rather than lost; a call whose file changed since it was read is refused with both digests (`file changed by another writer ...; re-read and retry`) and leaves the file untouched. A successful edit ends with a receipt line — the path, the byte delta, and the digest of what is now on disk, for example `wrote internal/tools/x.go (375 -> 396 bytes, sha256:1a2b3c4d5e6f)`. Read that line: a delta that shrinks or repeats what an earlier call reported in the same turn means the write did not land as expected.
