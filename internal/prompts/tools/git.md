Run a git command (status, diff, log, show, branch, add, commit, push, pull, fetch). The `action` parameter selects the operation; `flags` accepts ONLY dash-prefixed options like `["--oneline", "-5", "--stat"]` — never put branch names, file paths, or refs here; `paths` targets file paths, branch names (for branch), or revision refs (for show/log/diff); `message` is required for `commit`; `timeout` caps a command's runtime. For `commit`, `paths` scopes the commit to those paths (they are passed after `--`, so a path is never read as a flag) — a commit without `paths` commits everything staged. Read-only actions (status, diff, diff_cached, log, show, branch, fetch) are safe; mutating actions (add, commit, push, pull) require approval unless approval gating is enabled. `branch` is read-only only when it merely lists or inspects refs (bare `branch`, `--list`, `-a`, `-r`, `--show-current`, `--contains`, `--merged`, `--no-merged`, `--points-at`, `--sort`, `--format`); any mutating option (-d, -D, --delete, -m, -M, --move, -c, -C, --copy, -f, --force, -u, --set-upstream-to, --unset-upstream, --edit-description) and any unrecognized option make the call a mutating action that requires approval — `-D` deletes a branch even when its commits are unmerged, whereas `-d` refuses; likewise branch names passed in `paths` without a listing flag create branches and require approval.
